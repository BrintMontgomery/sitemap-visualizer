# Phase 2: run and acquisition boundary

`js/contracts.js` is a local classic script loaded before the application. It exposes the frozen `SitemapContracts` object; Node tests may also require it. There are no acquisition adapters or graph mutations in this phase. The mode map contains an unavailable explanation for every mode until its implementation is shipped. It is not an authorization to execute a provider script.

`createRun({mode, rootUrl?, maxPages?, maxDepth?})` validates mode, optional root, and integer limits, returning frozen initial metadata. Defaults are 50 pages and depth 2. `normalizeUrl(input, base?)` returns `{ok, url}` or `{ok:false, issue}`. It uses browser URL resolution, removes fragments and default ports, resolves dot segments and normalizes scheme/host case. Query strings and trailing slash distinctions are preserved; `www` aliases are not merged. `uniqueUrls` deduplicates canonical strings; `inScope` compares exact normalized hostnames (including across HTTP and HTTPS), excluding subdomains.

As revised by Phase 10, non-HTTP(S) schemes and embedded credentials are rejected; explicit private/loopback IPv4, IPv6, `.local` and intranet hostnames are permitted. Selecting an internal root does not expand scope to its subnet. Exact normalized root-host scope remains unchanged. This supersedes the original Phase 2 address exclusion; see `docs/fetch-adapter.md` for the decision and limitations. The client cannot establish DNS resolution or inspect hidden redirect hops. The network adapter validates each observable final destination, but cannot prevent the browser from contacting an unseen redirect target. Browser CORS and local-network access policy still apply.

`validateResult(run, result)` returns either a frozen validated result or an issue, never graph data. It accepts bounded inert strings, with transport-specific content kinds and evidence classes. Required fields are `transport`, `status`, `contentKind`, `evidenceClass`, `payload`, `bytesRead`, `issues` (issue-code strings), `inputReference`, `startedAt` (ISO timestamp), and `elapsedMs`. Live results additionally require `resourceUrl`, `observedFinalUrl`, and a successful `httpStatus`; imports must not claim response metadata. Unobservable final URL/status, source origin for imports, and redirect history are null. Extra adapter fields do not enter the accepted result. Opaque or unreadable results cannot become evidence. Provider modes remain rejected until their own authenticated protocol/schema is implemented. Input text, names and URLs must be rendered as text via `textContent`, never as HTML. `observed-html` for imported HTML describes its source, not independent verification; `imported-link` is an assertion, and `sitemap-only` is inventory, not an edge.

The fixed initial limits are 2,000,000 bytes per resource, 10,000,000 per run, 250 pages, depth 4, 30 seconds per run, 10 seconds per request, two concurrent requests, one second between requests to a host, five observable redirects, 10,000 records, 20,000 elements and nesting depth 64. These are implementation choices, not established specification facts. `createBudget(run)` accounts for validated results and unique normalized page URLs, rejects repeated or forged results, and leaves accounting unchanged on rejection. Later adapters/controllers must enforce time, concurrency, rate, nesting, element, record and redirect limits during work; this phase supplies the limits and result/accounting boundary, not a running crawler. The browser may not reveal redirect counts. Payload bytes are measured as UTF-8 and declared bytes cannot be less than the measured payload.
